Calendar — calendar.html

All roles

A visual calendar of all scheduled jobs. Supports two view modes.

Views

ViewLayoutDetails
Month view 6×7 grid Today highlighted. Each cell shows coloured job chips (time + customer name). Click a cell → day panel slides in with full job list. Navigate with Prev/Next buttons.
Week view 7 columns, 7am–8pm time slots Jobs positioned by hour (56px per hour). Click a job chip → deep links to scheduled-jobs page for that job.

Data fetched

  • quote_requests: id, full_name, street_address, suburb, scheduled_date, scheduled_time, assigned_staff_ids, assigned_staff_colour where status='scheduled'

Deep linking

Clicking a job chip navigates to scheduled-jobs.html#view:<jobId>. The Scheduled Jobs page reads the hash and opens the job detail modal automatically.

Realtime

Subscribes to quote_requests changes — calendar re-renders when any job is updated.

My Schedule — my-schedule.html

All roles

Personal view showing only the jobs assigned to the currently logged-in staff member.

Features

  • Month navigation with Prev/Next and Today buttons
  • Jobs grouped by date; dates with no jobs are hidden
  • Each job card shows: time, customer name, full address, service chips, bed/bath count
  • Checklist progress bar with live checkbox ticking (saved to /api/save-checklist on change, 600ms debounce)
  • "Mark Complete" button → /api/complete-job
  • "Can't make it" button → /api/request-coverage (sets needs_coverage=true)

Data fetched

  • quote_requests: all scheduled jobs where assigned_staff_ids contains the current user's UUID, for the current month

Unscheduled Jobs — unscheduled-jobs.html

Manager+

The intake queue. New quote submissions land here as status='unscheduled'. Managers review and either schedule or archive them.

Job cards show

  • Customer avatar (initials), name, relative timestamp ("2 min ago" — updates every 30s)
  • Location + property type badge + dimensions (bedrooms/bathrooms)
  • Service chips
  • Actions: View (detail modal), Schedule (accept modal), Archive

Filters

Search bar filters by: name, suburb, state, services, property type. Results update live as you type.

Accept (Schedule) modal

FieldNotes
Date pickerCustom calendar dropdown
Time pickerHour (6am–8pm) + minute (00–59) selectors
Staff assignmentCheckboxes listing all active staff with their colour dot
RecurrencePill buttons: None / Weekly / Fortnightly / Monthly. Auto-detects from job's frequency field.
Internal notesManager-only notes stored in internal_notes
ChecklistDisplays the company checklist template (from MQ.store.rates.get().checklist). Copied to the job on accept.

API calls

  • Accept/schedule: POST /api/accept-job
  • Archive: direct Supabase update (sets status='archived') — no Function needed

Realtime

Subscribes to quote_requests — list auto-refreshes when a new quote arrives.

Scheduled Jobs — scheduled-jobs.html

All roles

All jobs currently in status='scheduled', grouped by date.

Job cards show

  • Time, customer name, address (with Google Maps link), phone
  • Staff assigned (with colour badges), service chips, property type, frequency
  • Checklist progress (x/y items complete, progress bar)

Actions

ActionMin roleNotes
View detailAllFull modal with all job info
EditManager+Opens edit modal for date/time/staff. Calls /api/update-job-schedule.
Mark CompleteAllCalls /api/complete-job. Triggers auto-clone if recurring.

Digest panel

A sidebar panel (on wide screens) shows recurring clients sorted by next scheduled date, and a count of one-off jobs.

Realtime

Subscribes to quote_requests changes.

Completed Jobs — completed-jobs.html

Owner only

Historical record of all completed jobs, sorted newest first.

Cards show

  • Customer name, completion date, address, service chips, property type badge
  • Green "Done" badge

Invoice management

  • Detail modal footer shows "Invoice Sent" badge if invoice_sent_at is set
  • Owner can enter an invoice reference number and mark it sent → updates invoice_reference and invoice_sent_at directly in Supabase

No edit/reschedule actions — completed jobs are read-only.

Clients — clients.html

Manager+

Customer relationship management. Managers create and manage client records and link them to their job history.

Client cards show

  • Client initials avatar, name, suburb/state, job count, date of last job
  • Follow-up needed badge if no activity in 60+ days

Filters

  • Text search by name/suburb
  • Toggle: "Follow-up needed" — shows only clients flagged for follow-up
  • Count badge in nav shows number of clients needing follow-up

Client detail panel

Clicking a client card expands a detail panel on the right (or below on mobile) showing:

  • Full contact info (name, email, phone)
  • Properties (with bedrooms, bathrooms, access notes, alarm code)
  • Job history for this client (from quote_requests where client_id=)
  • Quotes linked to this client

Actions

ActionNotes
Add clientModal with name, email, phone, address fields
Edit clientIn-place edits on the detail panel
Add propertyModal: bedrooms, bathrooms, living areas, clean type, access notes, alarm code
New quoteUses property details + company rates from MQ.store.rates to calculate a price estimate
Add jobLinks an existing quote request to this client
Import from quoteCreates a client record from a submitted quote
Delete clientCalls /api/delete-client — de-links jobs first, then deletes record

Follow-up logic

Calculated in JS (not stored in DB): needs_follow_up = days_since_last_job > 60. This is derived from the most recent scheduled_date or created_at across all jobs for that client.

Staff (HRIS) — staff.html

Owner only

Full HRIS (HR Information System) for managing staff. Displays as a spreadsheet-style table with a click-to-expand inline profile card (A2 design). Owner-only — staff cannot access this page.

HRIS table

Each row shows: name + avatar, status chip, phone, start date, and four document status columns (Police Check, Contract, Driver Licence, Right to Work) with a tick/missing indicator. Clicking any row expands an inline profile card below it. Only one row can be open at a time.

Expanded profile card (view mode)

Four columns:

  • Staff Member — avatar, name, role + cleaning level, status chip. Suspend/Reinstate button.
  • Personal Details — phone, address, start date, availability
  • Emergency Contact — name, relationship, phone. Missing fields highlighted in red.
  • Documents — Police Check, Contract, Driver Licence, Right to Work. Each slot shows On File / Missing badge + View link (if uploaded) + Upload/Replace button. HR Notes field (owner-only, never shown to staff).

Expanded profile card (edit mode)

Clicking "Edit Profile" switches the card to inline edit mode — all fields editable at once with a single Save button. No modal. Fields:

  • Name (admin-controlled — staff cannot change their own name)
  • Role, Cleaning Level, Start Date, Status
  • Colour — 10-swatch palette, selected colour saved to profiles.colour and used on calendar job chips
  • Phone, Street Address, Suburb, State, Postcode
  • Emergency contact (name, relationship, phone)
  • HR Notes (free text, owner-only, never exposed via API to staff)

On save: calls /api/update-profile, updates the summary row in-place, shows "Saved ✓". Cancel reverts to view mode.

Document upload

Upload/Replace buttons in both view and edit mode. Flow: file picker → /api/ensure-storage → Supabase Storage upload to {userId}/{docType} (no extension — overwrites same key) → signed URL (365 days) → /api/update-profile to save URL → card refreshes. All doc uploads are owner-only via API (update-profile.js enforces this server-side).

Add staff member

Modal: name, email, role, start date → /api/create-account → invite email sent. Table reloads automatically. Form fully clears on success.

Search

Live search filters by name or role. Clears row expand state (closes open card) when results change.

Data fetched

  • Table rows: direct Supabase query on profiles (excluding owner), selecting identity + doc URL columns
  • Expand card: POST /api/get-staff-profile — returns full HR field set for owners. Cached in memory per session (profileCache) to avoid repeat fetches.

All roles

Self-service page where staff can view and update their own contact details, address, emergency contact, and profile photo. Intentionally limited — staff cannot see HR notes, compliance documents, or other admin-only fields.

Training — training.html

All roles

Simple page for completing staff training. Contains training content (displayed as HTML) and a single "Mark as Complete" button that POSTs to /api/training-complete. On success, the button is hidden and a confirmation message is shown. The onboarding_complete field on the profile is set to true.

Settings — settings.html

Owner (most sections) / Manager+ (team section)

Company configuration and team account management.

Sections

Pricing Rates (owner only)

SettingType

Residential extras: oven, windows, balcony, garage, fridge, wallsDollar amounts each

Saved as company_settings.rates JSONB via /api/save-settings.

Checklist Template (owner only)

Editable list of default checklist items (11 defaults: vacuum, mop, benches, stove, sinks, toilets, shower, dust, bins, mirrors, handles). Can add/remove items. Saved as company_settings.checklist_template. This template is copied into each new job when it's accepted.

Message of the Week (owner only)

A textarea (max 280 chars) for a message displayed as a banner on the Dashboard Home for all staff. Saved as company_settings.message_of_week. Leave blank to hide the banner.

Team (manager+)

  • Avatar grid of all staff (managers see everyone; staff see only themselves)
  • Click an avatar to open the member detail panel
  • Edit role, availability preference, and colour for yourself (or all members if manager+)
  • Add new team member: name, email, role, start date → /api/create-account sends invite email
  • Reset password: sends reset email via /api/reset-password
  • Delete account (owner only): /api/delete-account

Availability preferences

Staff can set their own work availability via pill buttons:

  • Wants more work — shown with green dot in Team Availability widget
  • Comfortable — amber dot
  • I'm full — red dot

Stored in profiles.availability as { work_preference: '...' }.

Onboarding — onboarding.html

New staff (invited status)

A 4-step wizard that new staff complete after setting their password. Auth.js redirects any user with status='invited' and role != owner to this page instead of the dashboard.

Steps

StepFieldsValidation
1 — Personal First name, last name, phone Names non-empty, phone 8+ digits
2 — Address Street address, suburb, state (dropdown), postcode All required, postcode numeric 4 digits
3 — Emergency contact Name, phone, relationship All required, phone valid
4 — Agreements 3 checkboxes: Employment Agreement, Company Policies, Privacy Policy All 3 must be checked to proceed

Document upload

Compliance documents (police check, licence, right to work) are admin-upload only via the HRIS page. Staff no longer upload these during onboarding. Onboarding only collects personal details, address, emergency contact, and policy agreements.

Submission

Calls /api/update-profile with all collected data plus onboarding_complete: true and agreement timestamps. On success, redirects to dashboard/index.html after a 2.4s success animation.

Session persistence

Current step is saved in sessionStorage as mq_ob_step so the user can resume if they accidentally navigate away.

Admin bypass: An "Admin Skip" button is visible to owner/manager roles for testing purposes. It bypasses all validation and advances steps directly.
