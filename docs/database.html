Database Schema

MyQuest uses Supabase (PostgreSQL) for all persistent data. This page documents every table, its columns, and the Row Level Security policies. Schema changes are tracked as SQL migration files in /supabase/migrations/.

Source of truth: The SQL migration files in /supabase/migrations/ define the schema. Some columns were added directly in the Supabase dashboard and recorded in migrations retroactively with IF NOT EXISTS guards.

Storage: staff-documents

A private Supabase Storage bucket used during onboarding to store staff compliance documents.

  • Bucket name: staff-documents
  • Access: Private — not publicly accessible
  • Path structure: {userId}/{filename}.{ext}
  • Allowed types: PDF, JPG, PNG (max 5MB per file)
  • Documents uploaded: National Police Check (required), Driver's Licence (required), Right to Work (optional)
  • URLs: Signed URLs generated for 365 days at upload time, stored in profiles.*_url columns
  • Bucket creation: /api/ensure-storage creates the bucket idempotently before onboarding uploads begin
  • Deletion: /api/delete-account lists and deletes all files under {userId}/ before deleting the auth record

Row Level Security Summary

TableSELECTINSERT / UPDATE / DELETE
quote_requests Authenticated users (staff see all scheduled jobs; RLS may restrict certain statuses) Service role only (via Cloudflare Functions)
profiles Authenticated users; own row always readable; all rows readable by manager+ (RLS checks role) Service role only (via Cloudflare Functions)
clients Authenticated users (manager+) Authenticated users (manager+) for insert/update; service role for delete
company_settings All authenticated users (needed so staff can load checklist template) Service role only (via /api/save-settings)
staff-documents bucket Owner of files (authenticated, matching userId path prefix) Authenticated users for upload to own path; service role for delete
