Emails & Cron Jobs

MyQuest sends transactional emails via Resend and runs scheduled tasks via a separate Cloudflare Worker (the Reminder Worker) with cron triggers.

  2. Email Catalogue

Resend Integration

All transactional emails are sent via Resend. The API key is stored in the RESEND_API_KEY Cloudflare environment variable.

Emails are sent from hello@myquest.au. All email sending happens inside Cloudflare Functions — never from the browser.

Basic Resend call pattern

const emailRes = await fetch('https://api.resend.com/emails', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${RESEND_KEY}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    from: 'MyQuest <hello@myquest.au>',
    to: [customerEmail],
    subject: 'Your cleaning is confirmed',
    html: `<p>We'll be there on ${date} at ${time}.</p>`,
  }),
});

Email Catalogue

All emails sent by the system, grouped by trigger:

Customer emails (outbound)

EmailTriggered bySent toContent
Quote received /api/submit-quote Customer "Thank you for your enquiry. We'll be in touch shortly." Confirms the details submitted.
Job confirmed /api/accept-job Customer "Your cleaning is booked for [date] at [time]." Includes address confirmation and staff name(s).
Job reminder /api/send-reminders (daily cron) Customer "Reminder: your cleaning is tomorrow at [time]." Includes access instructions (if set) and assigned staff names.
Job complete / thank you /api/complete-job Customer "Thank you for choosing MyQuest." Includes a review link and a "book again" CTA.

Staff emails (outbound)

EmailTriggered bySent toContent
Shift claimed confirmation /api/claim-job Claiming staff member Full shift details: date, time, customer name, address (with Google Maps link), access instructions if set.
Coverage claimed alert /api/claim-job Admin (ADMIN_EMAIL) Notification that an open shift has been claimed and by whom.
Urgent open shift alert /api/check-open-shifts (30-min cron) Admin (ADMIN_EMAIL) Table of unclaimed open shifts occurring within 4 hours. Throttled to max one alert per 2 hours per job.

Auth emails (Supabase)

These are sent by Supabase directly — not via Resend. See Supabase Auth Emails below.

EmailTriggered bySent to
Staff invite /api/create-account calls Supabase invite endpoint New staff member
Password reset /api/reset-password calls Supabase recovery endpoint Staff member

Reminder Worker

A separate Cloudflare Worker deployed independently from the main Pages site. It lives in /reminder-worker/ and is deployed with its own wrangler.toml.

Purpose

Cloudflare Pages Functions can only respond to HTTP requests — they can't run on a schedule. The Reminder Worker is a dedicated Cloudflare Worker that runs on cron triggers and calls the Pages Function endpoints with the CRON_SECRET to authenticate.

Configuration (reminder-worker/wrangler.toml)

name = "myquest-reminder-cron"
main = "src/index.js"
compatibility_date = "2026-06-11"

[triggers]
crons = [
  "0 21 * * *",    # Daily at 9:00pm UTC
  "*/30 * * * *"   # Every 30 minutes
]

Time zone: Cloudflare cron times are in UTC. "9pm UTC" = 7am AEST (UTC+10) or 6am AEDT (UTC+11). Adjust the cron expression if you need reminders sent at a specific Australian local time.

How it calls the Pages Functions

// In reminder-worker/src/index.js
export default {
  async scheduled(event, env, ctx) {
    const secret = env.CRON_SECRET;
    const baseUrl = 'https://myquest.au';

    if (event.cron === '0 21 * * *') {
      // Daily reminder
      await fetch(`${baseUrl}/api/send-reminders?secret=${secret}`);
    }

    if (event.cron === '*/30 * * * *') {
      // Open shift check
      await fetch(`${baseUrl}/api/check-open-shifts?secret=${secret}`);
    }
  }
};

Deploying the worker

cd reminder-worker
wrangler deploy

Supabase Auth Emails

Supabase sends two types of auth emails automatically — these are configured in the Supabase project dashboard → Authentication → Email Templates.

Invite email

Triggered when /api/create-account calls the Supabase invite endpoint. Contains a link to set-password.html (configured as the redirect URL in the invite call). The link contains a PKCE code parameter that set-password.js exchanges for a session.

Password reset email

Triggered when /api/reset-password calls the Supabase recovery endpoint. Also redirects to set-password.html. Same flow as the invite.

Redirect URL configuration: The invite and reset redirect URLs must be whitelisted in Supabase under Authentication → URL Configuration → Redirect URLs. The production URL (https://myquest.au/set-password.html) must be listed there.

Customising auth email templates

Email templates are set directly in the Supabase dashboard — they are not stored in this repo. If you need to update the invite or reset email copy, go to: Supabase Dashboard → Project → Authentication → Email Templates.
