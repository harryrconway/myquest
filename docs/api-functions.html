API Functions

All backend logic lives in /functions/api/ as Cloudflare Pages Functions (Workers). Each file maps to a URL: /functions/api/accept-job.js → POST /api/accept-job. All functions handle CORS via an onRequestOptions handler.

Auth pattern: Every authenticated function follows the same pattern — extract the Bearer JWT, call Supabase /auth/v1/user to verify it, then fetch the caller's profile to get their role. Requests without a valid JWT or without the required role return 401 or 403.

POST /api/submit-quote

Public — no auth required Turnstile protected

Receives a new quote from the public website form. Validates Turnstile, inserts the quote, sends confirmation email to the customer.

Request body

{
  "full_name": "Jane Smith",
  "phone": "0412345678",
  "email": "jane@example.com",
  "suburb": "Glenelg",
  "services": ["General Clean"],
  "notes": "Weekly preferred",          // optional
  "cf-turnstile-response": "<token>"
}

Response

{ "success": true }
// or
{ "error": "Invalid Turnstile token." }

Side effects

  • Inserts a row into quote_requests with status='unscheduled'
  • Sends a "thank you" email to the customer via Resend

POST /api/accept-job

Manager+

Schedules an unscheduled job — sets its date, time, assigned staff, recurrence, and checklist, then emails the customer a confirmation.

Request body

{
  "jobId": "uuid",
  "scheduledDate": "2026-07-01",       // required
  "scheduledTime": "09:00",             // required
  "assignedStaffIds": ["uuid", ...],
  "assignedStaffColour": "#FFD400",
  "assignedStaffName": "Jane, Bob",
  "internalNotes": "Key under mat",    // optional
  "recurrence": "weekly",              // none | weekly | fortnightly | monthly
  "checklistTemplate": [               // array from company_settings
    { "id": "item-1", "text": "Vacuum all floors" }
  ]
}

What it writes

  • status → 'scheduled'
  • scheduled_date, scheduled_time
  • assigned_staff_ids, assigned_staff_colour, assigned_staff_name
  • internal_notes, recurrence
  • checklist — template items with done: false added
  • job_accepted_at, updated_at

Side effects

  • Sends confirmation email to customer: "We'll be there on [date] at [time]"

POST /api/complete-job

All authenticated roles

Marks a job as completed and auto-clones the next occurrence for recurring jobs.

Request body

{ "jobId": "uuid" }

What it writes

  • status → 'completed'
  • job_completed_at — current timestamp

Recurrence auto-clone logic

If recurrence is not 'none':

  1. Find all future instances in the series (same recurrence_parent_id)
  2. If future instances exist, calculate next date from the latest one
  3. If no future instances, calculate from the job being completed
  4. Create a new quote_requests row as a clone with:
    • Same staff, address, services, property details
    • New scheduled_date (+ 7/14/30 days based on recurrence)
    • Fresh checklist with all done: false
    • status='scheduled', recurrence_parent_id pointing to original job

Side effects

  • Sends a thank-you email to the customer with a review link and book-again CTA

POST /api/request-coverage

All authenticated roles

Staff flags they can't make an assigned job. Opens it as an available shift for others to claim.

Request body

{ "jobId": "uuid" }

What it writes

  • needs_coverage → true
  • coverage_requested_by → caller's user ID
  • coverage_requested_at → current timestamp

POST /api/claim-job

All authenticated roles

A staff member claims an open shift. Uses a conditional PATCH to prevent race conditions (double-claims).

Request body

{ "jobId": "uuid" }

What it writes (conditional — only if needs_coverage is still true)

  • needs_coverage → false
  • assigned_staff_ids — removes original requester, adds claimer
  • assigned_staff_name, assigned_staff_colour — updated
  • coverage_claimed_by, coverage_claimed_at

Side effects

  • Email to claimer: shift details, address, maps link, access instructions
  • Email to admin: notification of coverage claimed

POST /api/save-checklist

All authenticated roles

Saves the current checklist state for a job. Called on every checkbox toggle (debounced 600ms on the client).

Request body

{
  "jobId": "uuid",
  "checklist": [
    { "id": "item-1", "text": "Vacuum all floors", "done": true },
    { "id": "item-2", "text": "Mop hard floors", "done": false }
  ]
}

What it writes

  • checklist JSONB column on the job row

POST /api/create-account

Owner only

Invites a new staff member. Creates a Supabase Auth user via the invite endpoint and upserts a profiles row.

Request body

{
  "email": "newstaff@example.com",
  "name": "Bob Jones",
  "role": "junior-cleaner",
  "cleaning_level": 1            // optional
}

Response

{
  "success": true,
  "id": "uuid",
  "message": "Invitation sent to newstaff@example.com"
}

What it writes

  • Supabase Auth invite (sends email to staff member with link to set-password.html)
  • Upserts profiles row: { id, email, name, role, cleaning_level, status: 'invited' }

Edge case: "already registered"

If Supabase returns an "already registered" error, the function checks for an existing profile row. If no profile exists (orphaned auth record), it deletes the auth user and retries the invite.

POST /api/delete-account

Owner only

Permanently deletes a staff member. Cannot delete your own account.

Request body

{ "userId": "uuid" }

What it deletes (in order)

  1. All files under staff-documents/{userId}/ in Supabase Storage
  2. The profiles table row
  3. The auth.users entry (via admin endpoint)

POST /api/reset-password

Owner only

Triggers a password reset email for a staff member.

Request body

{ "email": "staff@example.com" }

Side effects

  • Calls Supabase /auth/v1/recovery endpoint
  • Staff receives an email with a link to set-password.html

POST /api/delete-client

Manager+

Deletes a client record. De-links any jobs referencing this client before deleting.

Request body

{ "clientId": "uuid" }

What it writes

  1. Sets client_id = null on all quote_requests rows where client_id = clientId
  2. Deletes the clients table row

GET /api/send-reminders?secret=…

Cron — secret required

Sends reminder emails to customers for jobs scheduled tomorrow. Triggered by the Reminder Worker cron (0 21 * * * — daily at 9pm). Protected by a shared secret passed as a query parameter.

Logic

  1. Calculate tomorrow's date
  2. Query quote_requests where scheduled_date = tomorrow, status = 'scheduled', and schedule_reminder_sent_at IS NULL
  3. Group by customer and send a reminder email with job details, access instructions, and assigned staff names
  4. Update each job: set schedule_reminder_sent_at = NOW() to prevent duplicate sends

Response

{ "sent": 3 }

GET /api/check-open-shifts?secret=…

Cron — secret required

Alerts the admin when there are unclaimed open shifts within a critical time window. Triggered by the Reminder Worker every 30 minutes (*/30 * * * *).

Logic

  1. Find jobs where needs_coverage = true, status = 'scheduled', and scheduled_date/time is within the urgent window (4 hours)
  2. Skip any job where coverage_alert_sent_at is within the last 2 hours (throttle re-alerts)
  3. Send an alert email to ADMIN_EMAIL with a table of urgent uncovered shifts
  4. Set coverage_alert_sent_at = NOW() on alerted jobs

Response

{ "checked": 5, "alerted": 1 }

POST /api/clear-jobs

Owner only — destructive

Bulk-deletes jobs and optionally all staff accounts. Used for testing/reset purposes. This is irreversible.

Request body

{
  "target": "all"
  // "unscheduled" | "scheduled" | "completed" | "archived" | "all"
}

What it deletes

  • All quote_requests rows matching the target status
  • If target = 'all': also deletes all auth users and profiles with role staff or manager (preserves owner)

Do not expose this in the production UI. It exists for dev/testing resets only. Ensure it is not accessible from any UI button in production.
